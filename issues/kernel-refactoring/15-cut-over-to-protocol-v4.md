# Cut over to protocol v4 and remove inferred turn routing

**Type:** AFK  
**Status:** completed

## What to build

Switch the kernel and all first-party clients/components to the approved v4 contracts in one coordinated breaking cutover. Remove the old inferred turn path instead of preserving aliases or dual protocol behavior.

Delete capability-based driver inference and its product-specific symptoms:

- `pickTurnReceiver` and equivalent inference;
- managed user-input metadata;
- `waiting_for_driver` and `turn_receiver_unavailable`;
- gateway wake/rejoin retry;
- old `message.user` dispatch as the authoritative acceptance boundary;
- uncorrelated `turn.done` lifecycle behavior.

Keep arbitrary topics for extension traffic and preserve active non-driver protocol features through their v4 mappings.

The shared Python client-v4 SDK temporarily isolates the current protocol v3
`hello`/`hello_ack` authentication exchange in its WebSocket transport adapter.
Remove that bridge during this cutover; after authentication, including all
client commands, queries, results, replies, errors, and events, already uses
protocol v4 envelopes.

## Acceptance criteria

- [x] Kernel validates and serves protocol v4 only.
- [x] Driver uses execution API; gateway uses client API.
- [x] No active source, test, docs, or generated testbed references remain for removed v3 turn semantics.
- [x] Runtime and worker protocol boundaries remain intact unless separately versioned.
- [x] Existing security, tenant, hook, tool, archive, and delete behavior has a v4 contract.
- [x] Full affected Go suite passes with `-race -count=1`.
- [x] Full affected bundle and frontend suites pass.
- [x] No generated artifacts are left by build/test steps.
